# 壁毯修复定位网校核

浏览器中建立 2–4 行 × 2–4 列矩形单元的定位网，拖动或录入织补后各网结的整数坐标，
录入 3–12 个原网纹样标记；点击“校核”后，应用把每个单元视为**连续双线性形变**，
将标记换算到织补坐标，并对整张网做**连续不翻折判定**（不以有限采样点替代）。

定位网校核通过后，还可配置 **1–4 条纹样引线伸缩限制**：为每条引线选择两个已有
标记作为端点，填写相对原网直线长度允许的最小、最大伸缩倍率。应用按引线与原网
网格线的**全部交点**把线段切成单元内片段，对每段双线性映射后的**二次曲线精确求
弧长**（闭式积分）后汇总，避免“跨越多个单元、端点看似合适却在中途被过度拉长”。

## 连续判定的数学依据

单元的织补映射为双线性插值 `P(s,t)`，其雅可比行列式 `J(s,t)` 关于 `(s,t)` 是双线性函数。
双线性函数在矩形域上的最小值必在某一角点取得（固定 t 时关于 s 线性，两端关于 t 亦线性），因此：

```
J(s,t) > 0  ∀(s,t)∈[0,1]²   ⇔   四个角点的 J 值均 > 0
```

检查 4 个角点即等价于检查单元内**任意内部位置**，这是严格的连续判定而非采样。
角点 J 值即该角点两条邻边向量的叉积；网结坐标为整数时 J 必为整数，故 `J > 0 ⇔ J ≥ 1`，无数值模糊地带。

- **翻折**：某角点 `J < 0`；**退化**：某角点 `J = 0`。
- 首项失败证据按**行优先单元顺序**与**固定角点顺序**（C0 左上 → C1 右上 → C2 右下 → C3 左下）报告。
- 相邻单元共享边：共享边两侧的双线性映射在边上退化为同一对端点的同一线性插值，
  结构化网格天然共用网结，并由 `checkSharedEdges` 显式核验。
- 只有全网通过时才输出纹样标记的换算位置，避免把失真坐标交给织补师。
- 网结拖动或任何字段修改都会立即使旧结论失效（页面提示重新校核）。

## 引线伸缩校核的数学依据

引线在原网上是连接两个标记的直线。为什么不能只比较织补后两个端点的距离？
双线性映射会把直线变成曲线：端点位置合适，并不保证引线中途没有被过度拉长。

1. **按网格线切片**：求引线与全部内部网格线（u=1..cols-1、v=1..rows-1）的交点，
   连同两端点按引线全长参数 λ∈[0,1] 排序去重（穿过网结时横竖线给出同一点），
   切成若干单元内片段，每段只属于一个单元。映射在共享边上连续，片段首尾相接。
2. **每段是二次曲线**：单元内片段的局部坐标 (s,t) 随参数 z∈[0,1] 线性变化，
   代入双线性映射 P(s,t) 后每条坐标关于 z 恰为二次多项式
   `Q(z)=A+Bz+Cz²`，速度 `Q'(z)=B+2Cz`。三点 z=0、½、1 唯一确定该曲线。
3. **精确弧长（闭式，非采样）**：速度平方 `f(z)=az²+bz+c`，令
   `k=4ac−b²=16(B×C)²≥0`（二维 Gram 行列式恒非负），则
   `L=[Φ(2a+b)−Φ(b)]/(4a^{3/2})`，其中
   `Φ(u)=½(u√(u²+k)+k·asinh(u/√k))`（k=0 时 `Φ=½u|u|`）为初等函数原函数。
   速度方向不变（B∥(B+2C) 且不反向）时弧长严格等于弦长，据此稳定处理
   恒等/仿射单元与浮点近退化情形。
4. **汇总与判定**：织补后长度 = 各片段弧长之和，实际倍率 = 织补长度/原网直线
   长度；倍率须落在闭区间 `[minRatio, maxRatio]`。任一网结、标记或引线字段
   修改后旧结论立即失效。

首项失败按**引线录入顺序**报告，类型依次为：端点无效（端点不是已有标记序号）
→ 原始长度为零 → 倍率超限，并附原始长度、织补长度与实际倍率等长度证据。
几何（翻折/退化）未通过时不进行引线校核。未配置 `leads` 的请求/响应与原来
完全一致（不含引线字段）。

## 运行（Docker Compose）

```bash
# 启动 Web 服务（宿主机端口可配置，默认 8080）
WEB_PORT=9000 docker compose up --build web
# 打开 http://localhost:9000

# 一次性验收：代码测试 → 构建 → 健康与校核样例冒烟，以退出码报告结论
docker compose up --build --exit-code-from verify
echo $?   # 0 = 验收通过
```

- Web 服务健康检查：`GET /healthz`（Compose healthcheck 与 Dockerfile HEALTHCHECK 均使用）。
- 校核 API：`POST /api/verify`，请求体 `{rows, cols, knots, markers, leads?}`，
  与浏览器页面共用同一数学模块 `src/shared/bilinear.js`。`leads` 可选，每项为
  `{from, to, minRatio, maxRatio}`（端点为 markers 的下标，0 起）。配置且通过时
  响应含 `leads`（每条的原始长度、织补长度、实际倍率与经过的单元片段
  `segments`）与 `leadFailure:null`；引线失败时 `ok:false, stage:'leads'`，
  `leadFailure` 给出按录入顺序的首项失败与长度证据；未配置时无引线字段。

## 本地开发（Node ≥ 20，无第三方依赖）

```bash
npm test          # 单元测试（node:test）
npm run build     # 构建 dist/（含恒等网格自检）
npm start         # 构建并启动服务（PORT 环境变量可改端口，默认 8080）
npm run smoke     # 对运行中的服务做健康 + 校核样例冒烟
```

## 目录结构

```
src/shared/bilinear.js   # 核心数学：双线性映射、连续不翻折判定、标记换算、
                         #   引线按网格线切片与二次曲线闭式弧长（浏览器/服务端/测试共用）
src/server.js            # 静态服务 + /healthz + /api/verify
src/public/              # 浏览器页面（画布拖动、字段录入、引线配置、结论展示）
scripts/build.js         # 构建：自检 + 组装 dist/ + SHA-256 清单
scripts/smoke.js         # 冒烟：健康检查 + 恒等/翻折/退化/无效坐标 + 引线伸缩样例
test/                    # node:test 单元测试
Dockerfile               # 单镜像：构建期自检，运行时非 root
docker-compose.yml       # web（健康检查、端口可配）+ verify（一次性验收，退出码报告）
```
